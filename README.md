# GitHub Branching & Collaboration Workflow

## Project Overview
This repository demonstrates GitHub branching and collaboration practices as part of my DevOps internship.

## Objective
To understand how multiple developers can work on the same repository using Git branches, commits, pull requests, and merge conflict resolution.

## Branching Strategy

The repository follows this branching structure:

- **main:** Contains the stable version of the project.
- **development:** Used to combine and test contributions.
- **feature branches:** Used for individual tasks and modifications.

## Branch Naming Convention

Feature branches follow this naming format:

`feature/task-name`

Example: `feature/update-readme`

## Collaboration Workflow

1. Create a feature branch from development.
2. Make changes to project files.
3. Commit the changes with a meaningful message.
4. Push the feature branch to GitHub.
5. Create a Pull Request targeting development.
6. Request a peer review.
7. Merge the approved Pull Request into development.

## Merge Conflict Resolution

Merge conflicts occur when different branches make incompatible changes to the same part of a file.

The conflicting changes are reviewed, resolved, committed, and pushed to GitHub.
